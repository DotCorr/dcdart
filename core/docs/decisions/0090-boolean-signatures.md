# ADR-0090 — Boolean signatures

Status: implemented in development; platform checks pending.
Date: 2026-09-14.

Recognize dart:core bool by its fully qualified canonical reference, without
resolving a declaration absent from the trimmed Kernel component. It maps to
DCBool in parameters, returns, function pointers and raw-pointer pointees.
Capture scanning likewise traverses interface type arguments without resolving
the class declaration. Equality operands and variable initializers are still
visited, including the negative captured-boolean regression.

C headers use bool from stdbool.h (also valid in C++). LLVM calls and definitions
use zeroext i1 on Apple, x86-64 SysV, Windows x64 and wasm32. Linux ARM64 uses i1
without that attribute. These match signatures generated by the installed Clang
for a C _Bool function on each target. Windows bool extension is independent of
the existing narrow-integer rule: Windows narrow integers do not gain attributes.

The call-statements regression now exercises boolean local parameters/returns,
boolean locals, C-to-DCDart calls, callbacks in both directions, and pointer
loads/stores with false and true. Its generated header is checked as C++17 too.
These tests complement the existing boolean branch/loop regression. Generic
core int and inferred Null returns are separate outstanding requirements.
